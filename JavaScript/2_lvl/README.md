# Level 2 — массивы: новый массив и in-place (LeetCode-style)

Этот уровень перекликается с задачами вида **Remove Element**, **Move Zeroes**, **разворот массива** на [LeetCode](https://leetcode.com): отделить «фильтрацию с новым массивом» от **изменения исходного массива** с возвратом **длины значимой части** или разворотом **на месте**.

## Задачи

| Файл | Условие (кратко) | Паттерн |
|------|------------------|---------|
| `2.1_lvl.js` | Удалить элементы **меньше нуля** | новый массив + `push` (как ручной `filter`) |
| `2.2_lvl.js` | Сжать массив, убрав отрицательные (**in-place**) | два индекса: читаем `i`, пишем в `arr[count]`; вернуть `count` |
| `2.3_lvl.js` | Удалить заданное значение из массива (**in-place**) | тот же write-index; исключить `val` (аналог [Remove Element](https://leetcode.com/problems/remove-element/)) |
| `2.4_lvl.js` | В комментарии: палиндром массива; **в коде** — разворот массива **на месте** | **два указателя** `left` / `right`, обмен `swap` до схождения |
| `2.4b_lvl.js` | Развернуть массив **на месте** | заглушка: реализуй ту же идею, что в `2.4_lvl.js` |

### Уточнение по `2.4_lvl.js`

В файле заявлена «проверка палиндрома массива», но реализован **reverse in-place** — типичный подмодуль для многих задач (в т.ч. палиндром проверяют двумя указателями **без** полного разворота, либо после разворота сравнивают копии — зависит от формулировки). Имеет смысл позже **согласовать комментарий с кодом** или добавить отдельную функцию `isPalindrome`.

Запуск:

```bash
node 2_lvl/2.1_lvl.js
```

## Шпаргалка: «новый массив» vs in-place

### Новый массив (`2.1_lvl.js`)

```javascript
const result = [];
for (let i = 0; i < arr.length; i++) {
  if (/* условие сохранить */) {
    result.push(arr[i]);
  }
}
return result;
```

Исходный `arr` не меняется.

### In-place с индексом записи (`2.2`, `2.3`)

```javascript
let write = 0;
for (let i = 0; i < arr.length; i++) {
  if (/* элемент оставляем */) {
    arr[write] = arr[i];
    write++;
  }
}
return write; // длина префикса «валидных» элементов
```

После вызова **смысл имеют** только `arr[0..write-1]`; хвост массива часто не важен (как в условиях LeetCode).

### Два указателя по краям (`2.4`)

```javascript
let left = 0;
let right = arr.length - 1;
while (left < right) {
  // swap arr[left], arr[right]
  left++;
  right--;
}
```

**Когда:** разворот, палиндром, пара суммы в **отсортированном** массиве (другие задачи).

## Связь с заметками Level 0

- Тот же **линейный проход** и мысленное **Read → Loop → Check → Update → Return**.
- In-place — это всё ещё один массив, но **инвариант**: «первые `write` позиций уже заполнены правильно».

Когда освоишь `filter` / `splice` в JS, вернись к этим задачам и сравни: **учебная ручная версия** помогает понимать, что делают стандартные методы и как оценивают память на собеседованиях.
